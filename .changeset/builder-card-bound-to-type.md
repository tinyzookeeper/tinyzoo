A page block can show the entries of one of the site's own content types with a card made of small blocks, each of which names the field it shows. Experimental, like the site's own content types: the admin offers such a block only with `NUXT_CMS_CUSTOM_TYPES=on`; without it, and for every block that does not use the new fields, nothing changes.

- **For a developer.** `customTypeCard()` is the field of a page block that holds which type the block shows, the order and how many at most (a `CmsBinding` with `type`, `order` and `limit`). The card is the block's own list of small blocks, and a small block names the field it shows with `customTypeFieldRef({ takes })`, where `takes` lists the kinds of field it shows. A reference is stored as a text (the field's key, `slug` for the entry's own page, empty for none), so the stored blocks, the generated types, OpenAPI and the client treat it as one. It is a field of a block inside a block that holds a card, or of a block in a list inside one of those; anywhere else the config does not load, and the error names the path. A block holds one card.
- **The kinds.** `customFieldKind(field)` says what a field of a site's own type is for a block: `text`, `longText`, `richText`, `number`, `date`, `choice`, `yesNo`, `picture`, `gallery`, `file`, `link`, `email`, `color`, `relation`, and `page` for the entry's own page. `CUSTOM_FIELD_KINDS` lists them and `CUSTOM_PAGE_FIELD` is `slug`. `GET /api/content/_types` gives each field its `kind`.
- **Saving.** The server checks a new reference against the site's types: a field the type does not have, a hidden one, one whose kind the block does not take, or any field while the block has no type yet is refused with its path, as the other errors of a block are. An empty reference is accepted. A reference that is already stored is kept as it is, so a page stays saveable after its type changed.
- **The type editor.** Where a field or a type is used, the blocks that name something the site does not have, and the refusal to remove a field or a type that blocks still show count the references of a card's blocks, at both levels, as they count the other blocks that show a type. A small block whose field is gone (the section now shows another type) says so in the form.
- **For an owner.** The card's block asks for the content type, the order and how many entries. A small block asks which field it shows: it offers only the type's fields that fit it, each with its name and the icon of its kind. A field that was removed from the type, or one that no longer fits, says so under the choice and can be replaced or cleared.
- **New text:** *Choose what the section shows first.*, *Choose a field*, *This field is no longer in {type}: {key}*, *{name} does not fit this block.*, *{type} has no field this block can show.* and *Clear*, in English, Czech and German.
